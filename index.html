01 / CASO

Qué problema resuelve

Un vehículo llega a la cámara del parking. El sistema comprobaría la iluminación, activaría una luz auxiliar si hace falta y capturaría una fotografía. Localizaría y leería la matrícula, propondría su tipo y país y mostraría el resultado con su confianza. Una persona revisaría las decisiones que afecten al conductor.

Entrada

Fotografía de prueba

Imagen y metadatos mínimos: identificador ficticio y momento de captura. No se necesitan datos personales reales para esta propuesta.

Procesamiento previsto

Detectar, recortar, leer

Comprobación del archivo, mejora de imagen, detección de región, OCR, normalización y comprobación del patrón esperado.

Salida

Resultado explicable

Texto propuesto, región señalada, confianza, estado del formato y aviso cuando la lectura sea dudosa.

Límite de la propuestaQue una cadena tenga un formato plausible no demuestra que la matrícula exista, pertenezca a ese vehículo o esté autorizada para entrar. Una persona revisaría lecturas dudosas y cualquier decisión que afecte al acceso.

Alternativa de alto rendimiento

C++

C++ destaca por su rendimiento al procesar imágenes, pero es más complejo de desarrollar. Para este proyecto priorizamos la sencillez y el tiempo de implementación. La elección de Python busca rapidez de desarrollo, no afirmar que su ejecución sea más rápida que la de C++.

Aplicación e IAPython coordinaría el procesamiento y el componente de IA. HTML y CSS presentarían la interfaz, y JavaScript gestionaría la interacción del navegador. JavaScript / Node.js también sería útil para un servidor que recibiera los resultados de la cámara, aunque no sería nuestra primera opción para desarrollar el reconocimiento de imágenes.

05 / ESTRUCTURA

Del vehículo al resultado

Ocho etapas del funcionamiento previsto en el parking. Las pruebas pueden utilizar fotografías ficticias o autorizadas.

1

Llegada del vehículo

El conductor se sitúa ante la cámara de entrada o salida del parking.

2

Comprobar iluminación

Si la luminosidad es insuficiente, se enciende una luz auxiliar antes de la captura.

3

Capturar y validar

Se recibe la fotografía y se comprueban formato, integridad y calidad. Si falla, se solicita otra.

4

Preparar la imagen

Se ajustan tamaño, contraste u orientación para facilitar el análisis.

5

Detectar y leer

El primer modelo localiza la matrícula; el sistema de OCR obtiene sus caracteres. Si no se detecta, se pide otra captura o revisión.

6

Identificar y validar

El segundo modelo propone el tipo de placa y el país. Se comprueba el formato y la confianza; no se deduce la localidad ni la identidad del titular.

7

Revisión humana

Una persona revisa los casos dudosos y cualquier decisión que afecte al acceso o al cobro.

8

Mostrar el resultado

Se presenta matrícula, fecha, tipo, país propuesto y estado. Se registra lo necesario si procede.

Diagrama del funcionamiento

Antes de integrar los modelos

Prepararíamos imágenes etiquetadas con la posición de la matrícula, su texto, el tipo de placa y el país. Separaríamos los datos de entrenamiento, validación y prueba para comprobar la capacidad de generalización. Adaptaríamos dos modelos preentrenados: uno para detección y reconocimiento, y otro para tipo y procedencia.

Los componentes principales serían la cámara, el control de iluminación, la validación y preparación de imágenes, el detector y OCR, el clasificador de tipo y país, las reglas de validación, la API, el registro y la interfaz de revisión. Probaríamos distintas condiciones de luz, distancia y orientación antes de integrar los modelos.

Después de integrar: uso y reentrenamiento

La aplicación cargaría las versiones aprobadas y aplicaría el flujo de captura y reconocimiento a cada vehículo. Revisar una lectura no entrena automáticamente al modelo: las correcciones humanas se recopilarían como ejemplos para un reentrenamiento posterior, periódico y validado.

La nueva versión solo sustituiría a la anterior tras una evaluación y aprobación humana. Si empeora resultados importantes, se conservaría la versión anterior y se revisarían los datos y ajustes.

Pseudocódigo del flujo ampliado

función procesar_vehiculo():
    si luz_insuficiente(): encender_luz_auxiliar()
    imagen = capturar_fotografia()
    si no validar_imagen(imagen): devolver solicitar_nueva_captura()
    preparada = preprocesar_imagen(imagen)
    region = detectar_matricula(modelo_1, preparada)
    si region no existe: devolver solicitar_captura_o_revision()
    texto, confianza_lectura = ejecutar_OCR(region)
    tipo, pais, confianza_origen = clasificar(modelo_2, region)
    matricula = normalizar_texto(texto)
    resultado = preparar_propuesta(matricula, tipo, pais)
    si lectura_dudosa() o formato_invalido() o decision_afecta_conductor():
        resultado = revision_humana(imagen, resultado)
    mostrar_resultado(resultado)
    guardar_registro_si_procede(resultado)

Este resumen incorpora iluminación y clasificación al diseño general. El notebook conserva el pseudocódigo de detección y lectura aportado por el equipo.
